## Controlled Live Transition

NetworkManager was first started alongside networkd. It detected
`virtio_net`, created the automatic profile `Wired connection 1`, and obtained
`192.168.64.4/24`. A temporary duplicate address and route were expected while
both DHCP managers were active.

A three-minute systemd rollback was then armed before stopping networkd. The
live NetworkManager connection remained healthy for the full window. The timer
expired before the next validation turn resumed and correctly restored the
original networkd state at `02:18:53`. This was a deliberate safety rollback,
not a NetworkManager failure.

The proven transition was repeated with an atomic script that:

1. started and enabled NetworkManager;
2. required the virtio Ethernet device to reach NetworkManager state 100;
3. armed a ten-minute independent rollback timer;
4. disabled and stopped the five networkd units named by migration
   `1782002156.sh`;
5. masked both networkd and NetworkManager wait-online services;
6. reloaded NetworkManager and restarted systemd-resolved;
7. required a default route, successful DNS lookup, and successful HTTPS
   request;
8. canceled the rollback timer only after every check passed.

The transition completed with:

```text
NetworkManager.service              enabled, active
NetworkManager-wait-online.service  masked, inactive
systemd-networkd.service            disabled, inactive
systemd-networkd sockets            disabled, inactive
systemd-networkd-wait-online        masked, inactive
systemd-resolved.service            enabled, active
iwd.service                         enabled, active
```

The Archboot `.network` file remains byte-for-byte intact as a recovery input.
`systemd-network-generator.service` is disabled for future boots; its current
`active (exited)` state only records that it ran at the beginning of this boot.
