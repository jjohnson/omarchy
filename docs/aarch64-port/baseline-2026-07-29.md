`linux-aarch64` declares `provides=(linux=7.1.5)` and conflicts with `linux`.
`linux-aarch64-headers` declares `provides=(linux-headers=7.1.5)` and conflicts
with `linux-headers`. This confirms the proposed package-name mapping for this
Arch Linux ARM guest:

```text
linux         -> linux-aarch64
linux-headers -> linux-aarch64-headers
```

The installed preset is `/etc/mkinitcpio.d/linux-aarch64.preset`. It has one
`default` preset, uses kernel version `7.1.5-2-aarch64-ARCH`, and writes
`/boot/initramfs-linux.img`. The current mkinitcpio hooks are:

```text
base udev autodetect microcode modconf kms keyboard keymap consolefont block filesystems fsck
```

`pacman -Qk` reported no missing files for `linux-aarch64`, `limine`,
`limine-mkinitcpio-hook`, or `mkinitcpio`. UEFI boot entry `0006` is Limine at
`\EFI\BOOT\BOOTAA64.EFI`; it was the current boot entry at capture time.
Neither the bootloader, kernel, preset, nor initramfs was changed during
baseline collection.

## Guardrails

- Do not repartition or reformat the disk.
- Do not replace or modify the kernel, initramfs setup, Limine installation, or
  UEFI boot entries.
- Do not use the existing Armarchy checkout or its history as the port base.
- Build packages locally and inspect them before installing system-wide.
- Treat this VM as disposable, but preserve the recorded boot and graphics
  baseline throughout the first milestone.
